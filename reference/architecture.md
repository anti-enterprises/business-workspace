# Workspace Architecture

## Layers

```
Intent + Knowledge  →  Reasoning  →  Action

directives/  +  context/  →  orchestration/  →  execution/
                                   ↑
                                sources/  ←→  Pulse workspace (~/.pulse/workspaces/<id>/)
```

1. **Directives** declare intent: a desired outcome, required inputs, expected output. Human-readable, opinion-light.
2. **Context** is operational knowledge orchestration consumes at run time: operating rules, brand voice, snapshots of business profile / customers / offers. It is **not** the source of truth for Pulse.
3. **Orchestration** routes a directive through the correct workflow and chains execution tools. See `orchestration/routing.md` for the routing protocol.
4. **Execution** is the deterministic TypeScript runtime. APIs (`execution/apis/`), DB (`execution/db/`), GTM primitives (`execution/gtm/`), source sync (`execution/sync/`).
5. **Sources** are Pulse-aligned source catalogs. The repo's `sources/*.yaml` is mirrored to/from the Pulse workspace via `pnpm push:sources` / `pnpm pull:sources`.
6. **Pulse workspace** (`~/.pulse/workspaces/<id>/`) is external to this repo. It owns intelligence: identity, customer, offer, goals, position, atoms, hypotheses, directions, briefs.

## Source of truth boundaries

| Concern | Source of truth | Notes |
| --- | --- | --- |
| Identity / Customer / Offer / Goals / Position | Pulse `workspace.yaml` | Context snapshots refresh from here, not the reverse |
| Source catalogs (URLs, kinds, strategic roles) | Repo `sources/*.yaml` | Pushed to Pulse via `pnpm push:sources` |
| Operating rules, brand voice | Repo `context/` | Used by orchestration; not Pulse-relevant |
| Campaign / contact / message / signal-routing state | Repo Postgres (`execution/db/`) | Deterministic runtime state |
| Atoms, hypotheses, directions, briefs | Pulse workspace | Generated by `pulse` commands; consumed by orchestration |

## Runtime substrates

- **Deterministic code:** `execution/` (TypeScript, strict mode, Vitest)
- **Persistent state:** PostgreSQL via Docker Compose (`docker-compose.yml`, schema in `execution/db/schema.sql`)
- **Bootstrap:** `scripts/start.sh` — env defaults, DB up, schema apply/verify
- **Source sync:** `execution/sync/sync-sources.ts` (`pnpm sync:sources` / `push:sources` / `pull:sources`)
- **Reference docs:** this directory

## What does NOT live here

- AI/LLM prompt templates that are intent-shaped → `directives/`
- Per-customer or per-campaign assets → `offers/<offer>/`
- Pulse intelligence outputs (briefs, atoms) → consumed in place from `~/.pulse/workspaces/<id>/`, never copied into the repo
