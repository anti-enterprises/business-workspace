# Research Briefs

Shareable, snapshot copies of hyperresearch final reports. These are the externally-presentable versions — what we'd send a client, paste into a landing page, or include in onboarding.

## Relationship to the vault

The canonical, citable, lintable version of any brief lives in the hyperresearch vault at `research/notes/final_report_<vault_tag>.md`. The copy in this directory is a **snapshot at a point in time** — when the original vault report changes, this copy does not auto-update.

If a brief here matters for an external commitment (client deliverable, public-facing page), record the snapshot date in the brief's frontmatter and link the vault report. When the underlying evidence changes materially, decide explicitly: refresh the snapshot, or note that the snapshot is stale.

## What goes here

- Final reports promoted via the `research_briefs` directive (see `orchestration/skills/hyperresearch_handoff.md`).
- Reports written by hand that follow the same evidence-backed contract.

## What does NOT go here

- Vault scaffolding (`scaffold.md`, `loci.json`, interim notes) — those stay in `research/`.
- Operating decisions extracted from a brief — those go in `context/decisions/`.
- Pulse briefs — those live in `~/.pulse/workspaces/business-workspace/briefs/`.
